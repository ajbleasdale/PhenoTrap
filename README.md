# PhenoTrap

PhenoTrap is a workflow for semantic segmentation of fixed camera-trap imagery
for vegetation and phenological monitoring. The workflow covers image
pre-processing, semantic annotation, model training, inference, and extraction
of ecological metrics from classified imagery.

PhenoTrap fine-tunes a DeeplabV3/ResNet-101 CNN to isolate 13 unique environmental and vegetation classes. 
Inference from PhenoTrap can be utilised for monitoring habitat scene composition, snow cover analysis and vegetation greenup <br/>

## 1. Pre-processing

This stage prepares raw camera-trap imagery for annotation, model training and inference. The workflow selects timelapse images, standardises filenames, removes unwanted image regions and poor-quality images, and selects images for subsequent annotation.

Renaming is performed before image cropping to retain a consistent link between each image and the original camera records, including the date and time of capture. This also avoids potential issues associated with the loss or modification of image metadata during subsequent processing.

Run the required scripts in the following order:

1. **`1-1_timelapse-selection.py`** – Selects timelapse images from the raw camera-trap dataset while excluding images generated by other trigger modes.
2. **`1-2_file-rename.py`** – Renames images using a standardised naming convention containing deployment and image capture information. See [Naming Convention](Documentation/1_naming-convention.md) for further details.
3. **`1-3_header-footer-removal.py`** – Removes camera-generated headers and/or footers from images to prevent overlays such as timestamps, camera information or logos from influencing subsequent annotation and model training.
4. **`1-4_quality-control.py`** – Identifies and removes poor-quality imagery, including blurred, obscured, dark and near-infrared images. See [Quality control](Documentation/2_quality-control.md) for further details.
5. **`1-5a_image-selection-random.py`** – Randomly selects images from the pre-processed dataset for subsequent annotation.
6. **`1-5b_image-selection-exclusionary.py`** – **Optional alternative to `1-5a`.** Selects images while preventing images from the same deployment entering the annotation sample.



## 2. Dataset labelling

Run the required scripts in the following order:

## 3. Segmentation Model Training 
This stage fine-tunes the semantic segmentation model using the annotated and partitioned dataset produced during the previous stage. Model training is performed using DeepLabV3 with a ResNet-101 backbone implemented in PyTorch and Torchvision.

Run the required scripts in the following order:

1. **`3-1_PhenoTrap-training.py`** – Fine-tunes the segmentation model using the prepared training and validation datasets. Training progress, model performance and experimental parameters are recorded during training, and trained model checkpoints are saved for subsequent inference.
2. **`3-2_experiment-log-analysis.py`** – Optional. Summarises and visualises results recorded across training experiments to assist with comparison of model configurations and training performance.


**`experiment-log.xlsx`** – Template used by the training script to record experimental settings and model performance. Download and save a copy of this file in the experiment directory before training to ensure that results are logged correctly.

The trained model checkpoint produced during this stage is used for segmentation inference in Section 4.


## 4. Segmentation Inference 


This stage applies a trained PhenoTrap segmentation model to camera-trap imagery and processes the resulting predictions for subsequent analysis. The workflow generates semantic segmentation predictions, isolates class-specific regions of interest (ROIs), organises extracted imagery by class, and quantifies the predicted coverage of each class.

Run the required scripts in the following order:

1. **`4-1_PhenoTrap-inference.py`** – Applies a trained segmentation model to camera-trap images to generate pixel-level semantic segmentation predictions.

2. **`4-2_class-ROI-isolation.py`** – Uses the model predictions to isolate class-specific regions of interest (ROIs) from the original camera-trap images.

3. **`4-3_organise-ROI-to-class-folder.py`** – Organises the extracted ROI images into class-specific folders for subsequent analysis.

4. **`4-4a_quantify-class-from-model.py`** – Quantifies the number and proportion of pixels assigned to each class directly from the model inference outputs.

5. **`4-4b_quantify-class-from-mask.py`** – Alternative quantification workflow that calculates class coverage from previously generated segmentation masks.

6. **`4-5_reverse-ROI-to-mask.py`** – **Optional.** Reconstructs single-channel segmentation masks from previously extracted class-specific ROI images. This is intended as a recovery utility when the original segmentation masks are unavailable.

The outputs generated during this stage can be used directly for scene-composition analysis or processed further using the ecological applications described in Section 5.


## 5. Model Applications

This stage contains ecological applications that use outputs from the PhenoTrap segmentation workflow. These scripts are not intended to be run sequentially; instead, individual scripts can be selected depending on the analysis required. Applications currently include scene-composition analysis, snow-cover estimation, and vegetation greenness and phenology analysis using the Green Chromatic Coordinate (GCC).

### Scene composition

1. **`5-1a_dataset-scene-composition.py`** – Summarises the relative abundance of predicted vegetation and landscape classes across the complete dataset.

2. **`5-1b_deployment-scene-composition.py`** – Summarises class composition separately for individual camera-trap deployments.

### Snow cover

3. **`5-2a_snow-cover.py`** – Calculates snow-cover estimates from the predicted snow/ice class through time.

4. **`5-2b_snow-cover-comparison.py`** – Compares snow-cover estimates derived from PhenoTrap with an alternative snow-cover dataset or method.

### Vegetation greenness

The following scripts calculate Green Chromatic Coordinate (GCC) time series from vegetation regions isolated using the segmentation model. Different scripts are provided for analyses involving single or multiple sites and target classes.

5. **`5-3a_GCC-SS-SC-annual.py`** – Calculates annual GCC time series for a single site and single class.

6. **`5-3b_GCC-SS-MC-annual.py`** – Calculates annual GCC time series for a single site containing multiple class.

7. **`5-3c_GCC-MS-SC-annual.py`** – Calculates annual GCC time series across multiple sites with a single class per site.

8. **`5-3d_GCC-MS-MC-annual.py`** – Calculates annual GCC time series across multiple sites and multiple classes.

9. **`5-3e_GCC-MS-MC-continuous.py`** – Calculates continuous GCC time series across multiple sites and multiple classes.

#### SS = single site, MS = multiple sites, SC = single class, MC = multiple classes.

### Phenological metrics

10. **`5-4a_GCC-breakpoints-threshold.py`** – Derives phenological transition dates from GCC time series using a relative threshold approach.

11. **`5-4b_GCC-breakpoints-slope.py`** – Derives phenological transition dates from GCC time series using changes in the slope of the seasonal GCC curve.
